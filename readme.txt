標準カテゴリーとタグを、実行前プレビューと操作履歴、Undoを使って安全に整理します。

== Description ==

Term Stewardは、WordPress標準のカテゴリーとタグを管理画面から整理するプラグインです。

0.1.0では、次の操作に対応します。

* タームの名称変更と、明示した場合だけのslug変更
* 同じtaxonomy内にある既存タームへの統合
* WordPress全体で完全に未使用なタームの削除
* 実行前プレビュー
* 有界バッチによる実行と中断後の再開
* 操作履歴
* 対応可能な変更のUndo

relationshipの変更対象は、標準投稿タイプ`post`の公開済み投稿だけです。固定ページ、カスタム投稿タイプ、下書き、非公開、予約、承認待ち、ゴミ箱、自動下書きのrelationshipは変更しません。削除の安全判定では、WordPress全体のrelationshipを確認します。

カスタム投稿タイプとカスタムtaxonomyは0.1.0の対象外です。AI分類、CSV入出力、定期実行、Redoにも対応していません。

本番サイトで操作する前に、データベースとアップロードファイルをバックアップしてください。最初にステージング環境で確認することを推奨します。

サポートと不具合報告は[GitHub Issues](https://github.com/k-logic563/term-steward/issues)で受け付けています。ソースコードは[GitHubリポジトリ](https://github.com/k-logic563/term-steward)で公開しています。

== Installation ==

1. WordPress管理画面の「プラグイン > 新規プラグインを追加 > プラグインのアップロード」で配布ZIPを選びます。
2. インストール後にTerm Stewardを有効化します。
3. 「ツール > Term Steward」を開きます。
4. 「カテゴリー」または「タグ」タブを開き、対象を選択します。
5. 処理パネルで名称変更、統合、削除のいずれかを設定し、「計画に追加」を押します。
6. 「操作計画」タブを開き、「変更内容を確認」を押します。
7. プレビューモーダルで対象、変更後、影響数、削除または保持、警告を確認します。
8. 内容を変更せず閉じる場合は「キャンセル」、処理を開始する場合は「実行」を選びます。
9. 必要に応じて「操作履歴」からUndoの内容をプレビューし、「元に戻す」を実行します。

画面の利用には、カテゴリー管理と他の利用者の公開済み投稿を編集できる権限が必要です。

== Frequently Asked Questions ==

= どの投稿やtaxonomyが対象ですか？ =

0.1.0の対象taxonomyは標準カテゴリー`category`と標準タグ`post_tag`だけです。relationshipを変更する対象は、公開済みの標準投稿`post`だけです。カスタム投稿タイプとカスタムtaxonomyは対象外です。

= 「完全に未使用」とは何ですか？ =

公開済み投稿だけでなく、下書き、固定ページ、カスタム投稿タイプなどを含むWordPress全体でrelationshipが0件のタームです。対象外オブジェクトで使われているタームは削除しません。

= Undoですべての変更を必ず元に戻せますか？ =

いいえ。Undoは、元操作が実際に変更した差分だけを安全確認後に戻します。操作後に管理者が加えた変更や競合を上書きせず、取り消し不可または一部失敗として扱うことがあります。

= プラグインを削除すると履歴データも消えますか？ =

消えません。WordPress管理画面からTerm Stewardを削除しても、操作履歴テーブル、Operation Itemテーブル、Change Journalテーブル、DB schema version optionはデータベースに残ります。監査記録、中断・復旧情報、再インストール後の履歴確認、誤操作時の復旧情報を保護するためです。0.1.0には完全削除設定はありません。

= 旧開発名称のデータは自動移行されますか？ =

移行されません。Term Stewardは独立した`term_steward_*`テーブルとoptionを使用し、別プラグインの所有物である可能性がある旧識別子のデータを読み書きまたは削除しません。

= 操作前にバックアップは必要ですか？ =

本番サイトでは、データベースとアップロードファイルをバックアップし、復元手順を確認してから操作してください。

= 不具合はどこへ報告できますか？ =

[GitHub Issues](https://github.com/k-logic563/term-steward/issues)へ、再現手順と利用環境を添えて報告してください。パスワード、Cookie、nonce、APIキー、個人情報、データベースの完全なダンプは添付しないでください。
